# Инструкция по изменению (OKL Hospital — тестовая версия)

Все правки — в трёх файлах:

- `index.html` — разметка и тексты
- `assets/styles.css` — внешний вид (цвета, фон, шрифты)
- `assets/store.js` — данные и пользователи
- `assets/app.js` — логика (списки отделений, категории, права)

После правок просто обновите страницу в браузере (Ctrl/Cmd+Shift+R).

---

## 1. Стартовая страница (экран входа)

### Логотип
Логотип теперь вставлен как картинка и лежит в двух файлах:
- `assets/logo.png` — эмблема на бирюзовом фоне (для справки/фавикона);
- `assets/logo-white.png` — белая эмблема на прозрачном фоне (используется в интерфейсе).

Он уже подставлен во все места (экран входа, сайдбар, верхняя панель, брендинг).
**Чтобы сменить логотип — просто замените эти два файла** одноимёнными
картинками (квадратными, лучше 512×512, PNG с прозрачностью для `logo-white.png`).
Больше ничего править не нужно.

Места в `index.html`, где он подключён (если захотите изменить размер/обрамление):
`<img src="assets/logo-white.png">` внутри `.brand`, `.login-mark`,
`.side-brand .mark`, `.top-logo .mark`. Плитки-подложки — класс `.mark`/`.login-mark`
в `styles.css` (фон плитки = `--color-primary`).

### Фон стартовой страницы
Файл `assets/styles.css`, найдите `.login-visual{` (левая часть с градиентом).
- Сейчас: `background:linear-gradient(160deg,#05586A 0%,#067E96 52%,#0796B1 100%);`
- Чтобы поставить фото:
```css
.login-visual{
  background:
    linear-gradient(160deg, rgba(11,59,56,.75), rgba(13,148,136,.65)),
    url("assets/hospital.jpg") center/cover no-repeat;
}
```
- Узор из шестиугольников задаётся в `.login-visual::after` — можно удалить этот блок, если не нужен.
- Общий фон приложения — переменная `--color-bg` в самом верху `styles.css` (`:root`).

### Тексты на входе
Всё в `index.html` внутри `<div class="login-hero">`:
- заголовок — `<h1>Цифрова система…</h1>`
- подпись — `<p>Зручний доступ…</p>`
- бейдж — `<span class="login-badge">Надійно. Безпечно…</span>`

### Цвета бренда (teal и др.)
`assets/styles.css`, блок `:root{ … }` в самом верху — переменные
`--color-primary`, `--color-primary-hover`, `--color-primary-soft` и т.д.
Поменяли значение здесь — изменится во всём интерфейсе.

## 2. Пользователи (кто может заходить) и права по разделам

### Добавить пользователя
Файл `assets/store.js`, массив `users:` (в `SEED`). Добавьте объект:
```js
{ login: 'Іваненко', pass: 'мій_пароль', role: 'doctor', name: 'Іваненко І.І.' },
```
- `login` — вводится в поле «Прізвище» на входе (регистр не важен).
- `role` — одна из: `admin`, `doctor`, `viewer`.

Готовые тестовые аккаунты уже есть:
| Логин | Пароль | Роль |
|-------|--------|------|
| Бойко | okl2026 | admin (полный доступ) |
| Лікар | likar2026 | doctor (без настроек) |
| Перегляд | view2026 | viewer (только просмотр) |

> Важно: это тестовая проверка на стороне браузера. Для боевой версии нужен
> вход через Firebase Authentication и проверка роли **на сервере** (см. README).

### Кто что может редактировать
Файл `assets/app.js`, объект `PERMISSIONS` (в самом верху). Таблица «роль →
разделы». Поставьте `true/false`:
```js
const PERMISSIONS = {
  admin:  { patients:true,  operations:true,  journal:true,  report:true,  settings:true  },
  doctor: { patients:true,  operations:true,  journal:true,  report:true,  settings:false },
  viewer: { patients:false, operations:false, journal:false, report:false, settings:false },
};
```
Если у роли `patients:false` — у неё скрыта кнопка «Додати пацієнта», а
редактирование/удаление/выписка заблокированы.

Чтобы добавить новую роль — впишите её и в `PERMISSIONS`, и в `role` пользователя.

## 3. Что и где менять в каждом разделе

### Пациенты
- Демо-пациенты и **поля карточки** (схема): `assets/store.js` → `SEED.patients`
  (функция `p(...)` показывает набор полей).
- Список/таблица, KPI: `assets/app.js` → `renderPatients()`, `renderPatientKpis()`.
- Добавление/редактирование/выписка/удаление: `savePatient()`, `saveEdit()`,
  `openDischarge()/saveDischarge()`, `deletePatient()`.
- **Отделения** в выпадающих списках форм: `index.html` (блоки `id="addDept"` и
  `id="editDept"`).
- **Категории** и их цвета: `assets/app.js` → `catColor` и `civCats`
  (гражданские: Амбулаторно/Ургентно/Планово/Вибухові).
- **Триаж/стан** и цвета: `assets/app.js` → `stateColor`.
- **Типы выписки**: `assets/app.js` → `dischTypes`.

### Операции за добу
- Строки таблицы по умолчанию: `assets/app.js` → `opsRowsSeed`.
- KPI сверху: `assets/app.js` → `kpiOps`.
- Логика/сохранение: `renderOps()`, `saveOps()`.

### Звіт 08:00
- Данные таблицы (вкладки Військові/Усі): `assets/app.js` → `repRowsMil`,
  `repRowsAll`.
- KPI: `kpiReport`, `kpiReportAll`.
- Отделения для «Внести вільні ліжка»: `assets/app.js` → `bedsDepts`.

### Журнал за добу (автозаполнение из «Пациентов»)
- Список отделений журнала: `assets/app.js` → `jDepts`.
- Отделения, входящие в итог «Всього по РПЦ»: `assets/app.js` → `rpcDepts`
  (сейчас `['Гінекологія']` — допишите свои).
- Сопоставление названий отделений реестра → журналу: `jDeptMap`
  (напр. `'Неврологія' → 'Неврологія 1'`).
- **Логика автозаполнения** (что как считается): `jStatsFromPatients()` — по
  таблице; `fillJournalSummary()` — верхний блок «Підсумки надходження за добу».
  Столбец **ВІТ** = пациенты со статусом «Вкрай важкий» (правило можно
  изменить в `jStatsFromPatients`, строка с `s.vit++`).
- Ручным остаётся только блок «Додаткові показники за добу» (`index.html`).

### Статистика
- Всё считается из реальных данных: `assets/app.js` → `renderStats()`.

## 4. Как очистить всю базу

Три способа:
1. **В приложении:** «Налаштування» → пароль (любой) → блок **Очищення бази** →
   ввести слово `ОЧИСТИТИ` → кнопка. Данные сбросятся к начальным (демо),
   пользователи сохранятся.
2. **В консоли браузера** (F12 → Console):
   ```js
   localStorage.removeItem('okl_db_v1'); location.reload();
   ```
3. Программно: вызвать `DB.reset()`.

Где хранятся данные: браузер, ключ `okl_db_v1` (localStorage). У каждого
браузера/компьютера — своя копия (это тестовый режим).

## 5. Переход на реальный бекенд (Firebase / Cloud Functions)

Вся работа с данными изолирована в `assets/store.js` (пометки `// TODO(API)`).
Замените там localStorage на `fetch()` к вашему API
`europe-west1-okl-hospital-41197` — `app.js` менять не нужно.
Готовый шаблон: `assets/store.firebase.example.js`.

И обязательно вынесите проверку логина/роли на сервер — браузерные права из
раздела 2 боевую систему не защищают.
