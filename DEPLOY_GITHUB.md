# Публикация на GitHub Pages (тестовая версия)

Сайт полностью статический (HTML/CSS/JS), сборка не нужна — GitHub Pages
раздаёт его как есть. Пути к файлам относительные, поэтому работает и из
подпапки репозитория.

## Вариант A — через сайт GitHub (без командной строки)

1. Зайдите на https://github.com → **New repository**.
   Имя, напр. `okl-hospital-test`. Сделайте репозиторий **Private**
   (данные медицинские — публичным делать не стоит).
2. На странице репозитория: **Add file → Upload files**.
3. Перетащите **содержимое** папки `okl-test` (т.е. `index.html`, папку
   `assets/`, `README.md`), а не саму папку. Нажмите **Commit changes**.
4. **Settings → Pages** → Source: **Deploy from a branch** → Branch: `main`,
   папка `/ (root)` → **Save**.
5. Через 1–2 минуты вверху появится ссылка вида
   `https://<ваш-логин>.github.io/okl-hospital-test/`.
   Откройте — сайт работает.

## Вариант B — через командную строку (git)

```bash
cd okl-test
git init
git add .
git commit -m "OKL Hospital — test version"
git branch -M main
git remote add origin https://github.com/<логин>/okl-hospital-test.git
git push -u origin main
```
Затем включите Pages как в шаге 4 выше.

## Проверка после публикации

Откройте ссылку и пройдите чек-лист:
- вход тестовым аккаунтом (Бойко / okl2026);
- добавить пациента → появился в списке;
- отредактировать, выписать, удалить;
- журнал за добу заполнен автоматически;
- «Операції» и «Внести вільні ліжка» — сохранение;
- «Налаштування» → очистка базы;
- обновить страницу — изменения на месте (localStorage).

## Важно про данные и приватность

- Это тестовый режим: данные лежат **в браузере пользователя** (localStorage),
  на сервер не отправляются. У каждого посетителя — своя локальная копия.
- Логин проверяется на стороне браузера — это **не защита**. Для боевой версии
  подключите реальный бекенд и серверную авторизацию (см. `README.md` и
  `INSTRUCTIONS_RU.md`, раздел 5).
- Репозиторий держите приватным.
